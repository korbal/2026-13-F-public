# 2026-13-F-public

Public pages for the 13F1 Frontend-Backend class (2026/27): https://korbal.github.io/2026-13-F-public/

`index.html` is the home page, in English: lessons numbered as in the course's lesson plan (Lesson 1, 2, ...), then Git and GitHub, tests (oldest first) and the vizsgaremek. The class API is not linked from it; lessons link to it where they use it.

`api/` is a read-only JSON API for `fetch` practice (GitHub Pages serves it with `Access-Control-Allow-Origin: *`). `api/index.html` is the docs page with tasks; `api/index.json` lists the endpoints. Lessons live in one folder per series (`dom/`, `fetch/`, `git/`), as `NN-<slug>.html`, and the home page links one page per lesson, top to bottom: DOM, Fetch, Git. Every lesson opens in English; except Fetch 2 (English only for now), `?lang=hu` or the page's Magyarul button switches it to Hungarian (remembered per browser), and `?prep` is the teacher's view: no slides, every task opened with its solution already run, a Show task / Show solution toggle, Prev / Next (Alt+←/→), nothing saved. The two combine: `?prep&lang=hu`. `dom/01-data-to-elements.html` (DOM 1) and `fetch/01-what-is-json.html` (Fetch 1) are in the VS Code practice shape: slides, then eight tasks in a VS Code look-alike with the live page beside it. `fetch/02-data-from-a-server.html` (Fetch 2) is the same shape with five slides and six tasks: `fetch` from the class API with `async`/`await`; inside the practice, `fetch` answers from a copy of `api/` after a short wait (a wrong address gives a 404). Git is the teacher's own trainer, copied in from github.com/korbal/git-practice as `git/git-practice.html` (update it by copying that repo's `index.html` again); its `?prep` shows each lesson solved, with the commands that solve it. Old URLs only redirect: `dom/01-adatbol-elemek.html` to DOM 1, `fetch/01-json.html` to Fetch 1, `git/01-git-egyedul.html` and `git/01-save-points.html` to Git practice. `git/first-push.html` is a reading page, not a trainer: the first push (clone, config, add, commit, push, logout) with why each step is there, English with the same `?lang=hu` switch; it grows with pull, status and log later. `git/home-push.html` is its homework, same reading shape: generic steps with a check after each (`pwd`, `ls`, `git status`), push `rolam.md` from home on any OS (token on Mac/Linux, no OneDrive folder), then find the repo on the H: drive at school, `git pull` and `git log`. `fetch/02-json-utvonalak.html` is an older practice page, not linked, to be reworked into lesson format. The fetch series builds up to querying the API. `db/01-tables-from-a-story.html` (Lesson D1) starts the database-thinking series (D1–D4, before any SQL): slides, then seven tasks where they fill in tables on the page instead of writing code (a grid they can add tables, columns and rows to, words to pick, problems to tick), the story always open on the left; Check (Ctrl+Enter) replays the story against their rows. English only, `?prep` as in the other lessons. `db/02-ids-and-links.html` (Lesson D2) is the same shape: every row gets an id and the order points at its customer, pizza and courier (`customer_id`); a column ending in `_id` is tinted, and clicking one of its cells lights up the row it points at (or shows that no row has that id). Check replays the story and follows every id. `db/03-no-lists-in-a-cell.html` (Lesson D3) is the same shape: one order with several pizzas, so no list in a cell and no numbered columns; ask both ways, and a table in the middle (`order_items`: two pointers and the quantity). Check replays the story through the middle table. `db/04-your-own-app.html` (Lesson D4) brings D1–D3 together on their own app idea: they write a story (5–8 steps, each with a fact), build its tables with a live checklist of the rules a page can check without a story (ids, example rows, no lists, no numbered columns, every `_id` leads to a row, no copied names), then tick the paper checks for the replay, the swap with another team and the drawDB diagram; two extras (a gym app, a club event app) replay a given story. `term/01-where-am-i.html` (Lesson T1) and `term/02-make-move-run.html` (Lesson T2) teach the terminal before the backend: slides, then tasks in a simulated Git Bash (prompt, `pwd`, `ls`, `cd`, `mkdir`, `cp`, `mv`, `rm`, `cat`, `node`, Tab completion, ↑ history, Ctrl+C, real bash error messages) beside a live File Explorer of a fake H: drive. Every start shuffles the folders, so a task is done by looking, not by copying commands; the page checks where they ended up and what is on the drive, not what they typed. T2's last task is in their real VS Code terminal: they paste the output of `pwd` and `ls`. `backend/01-your-own-server.html` (Lesson 8) is the first backend lesson: they download `backend/lesson08-starter.zip` (an Express 4 `server.js` with `node_modules` included), run it in VS Code, and paste what the terminal or the browser shows; the page recognises the real node and Express messages (EADDRINUSE, Cannot find module, SyntaxError, …). No call to localhost from the page. Test folders never move, so old links keep working.

One folder per test (`testNN/`), linked from `index.html` (oldest first):

- `demo.html` – **Hibák**: the class's most common mistakes, wrong and right side by side (shown on the projector).
- `walkthrough.html` – **Javítás**: fix-it tasks built from the real mistakes; the page checks each fix itself.
- From Test 04: `solution/` – **Megoldás**, the full solution with step-by-step comments, plus `testNN-megoldas.zip`, the paper (`paper.html`) and the starting files (`testNN-kiindulo.zip`) for practising at home.

No student names, grades or feedback go here.
