Git homework: push at home, pull at school

The follow-up to the first push. Back to home

In class you pushed from the school computer. Now, at home, you add a file to the same repo from your own computer. In the next Git class you pull it down onto the school computer.

Home
School

The two computers never talk to each other, only to GitHub. That is how your team will work later.

Don't copy commands blindly. Where you see <…>, type your own thing there, without the < >. After every step, check that you see what you should. If you don't, stop there and fix it before going on.

Two commands that always tell you where you are

pwd
Prints which folder the terminal is in right now.
ls
Lists what is in that folder.

Both work in PowerShell, on Mac and on Linux. When anything looks wrong, run these two first.

At home

Get Git on your computer

Open a terminal (PowerShell on Windows) and check:

git --version

If it prints a version number, you have it: go on. If not, install it for your system from git-scm.com/downloads. On Windows the installer's defaults are fine. On a Mac, git --version offers to install it by itself. On Linux, your package manager (e.g. apt) has it.

Check: after installing, close the terminal and open a new one, then run git --version again. The old terminal doesn't know something was installed meanwhile.

Why: at school someone installed it for you. At home it's your job, but only once.

Pick a folder

Choose a folder where your repo will live and go there with cd. It must not be a folder that OneDrive, iCloud or Dropbox syncs (on Windows the Desktop and Documents often are). Your user folder (cd ~) is a good choice.

Check: pwd. If the path it prints contains OneDrive, go somewhere else.

Why: sync programs copy files behind Git's back, and that can break the repo. That was the problem with the drive at school too.

Download your repo

Your repo's HTTPS link is under the green Code button on its GitHub page. Copy it, then:

git clone <your-repo-link>
cd elso-repo

Check: ls shows README.md and hello.txt. git remote -v shows your own repo's link.

Why: you made hello.txt on another computer, and now it's here because it came through GitHub. clone also remembers where the repo came from (the remote), which is how push knows where to send things.

Tell Git who you are

Your own name, and the email your GitHub account uses. Same as in class.

git config user.name "<your name>"
git config user.email "<your github email>"

Check: git config user.name and git config user.email with nothing after them print what you set. If you see a < in it, you copied it wrong: set it again.

Why: this computer doesn't know what you set at school. GitHub uses the email to know the commit is yours.

Write rolam.md

With any text editor (in VS Code: code .), create a file called rolam.md in the elso-repo folder. Put in your name and your favourite song or game. Save it.

Check: ls shows rolam.md (not rolam.md.txt). git status lists it in red under Untracked files.

Why: Untracked means Git sees the file but isn't keeping track of it or saving it yet.

Add, commit, push

git add rolam.md
git status

Check: now it's green under Changes to be committed.

git commit -m "<say what you did>"
git push

The push asks you to log in:

  • Windows: a window pops up and you log in through the browser, like at school.
  • Mac, Linux: the terminal asks for Username and Password. GitHub does not accept your password here; it wants a token. Make one at github.com/settings/tokens/new, tick repo, Generate token, copy it, and paste that as the password. Nothing shows while you paste; that's normal.

Check: git status says Your branch is up to date with 'origin/main'.

Why: add picks what goes into the save, commit saves it on your computer, push sends it to GitHub. The commit message is for whoever reads it later: say what you did.

Check on GitHub

Refresh your repo's page: rolam.md is there. Open the list of commits: the school one and the home one are both there, both with your name. This is the proof of the homework.

At school (next Git class)

Find your repo on the H: drive

At school your repo belongs on the H: drive. Open PowerShell:

cd H:\
ls

Check: elso-repo is in the list. If it is, cd elso-repo, and git status says On branch main.

If it doesn't match, find out why:

  • No H: drive, or it doesn't hold your files: File Explorer → This PC. Find your own network drive and note its letter. Use that instead of H: today.
  • Right drive, but no elso-repo on it: you cloned it somewhere else last time. You don't need to hunt for it: GitHub has everything. Stay at the root of the drive and clone again: git clone <your-repo-link>. From now on it lives here.
  • not a git repository: you're not inside the repo folder. pwd, ls, then cd to the right place.

Why H:? It's your drive, not one computer's: it's there whichever school computer you sit at. A computer's own folders (Desktop, C:\temp) can be wiped, or next class you sit at a different machine.

Pull

git pull

Check: the output mentions rolam.md, and ls now shows it. (If you cloned fresh in step 1, it was already there and pull says Already up to date.)

Why: pull is the opposite of push: it downloads the commits from GitHub that this computer doesn't have yet. No login needed, because your repo is public.

Read the history

git log

If you see : or (END) at the bottom, press q to get out.

Why: find which commit was made at school and which at home. Same author, two computers, one history.

Before you leave

The pull didn't log in. If a login window did pop up, remove your login as in First push step 10.

If it breaks

Read the error message. All of it. Then pwd and ls.

git is not recognized / command not found
No Git, or you didn't open a new terminal after installing (step 1).
not a git repository
You're not in the repo folder. pwd, then cd into elso-repo.
destination path 'elso-repo' already exists
You already downloaded it here. cd elso-repo, then git pull.
Repository not found
Wrong link (or the < > are still in it). Copy it again from the green Code button.
Please tell me who you are
You skipped step 4. Do it, then commit again.
Password authentication is not supported
You typed your password instead of a token (Mac, Linux). See step 6.
403 / Permission denied to <someone else>
Someone else's GitHub login is saved on this computer. Windows: Credential Manager → git:https://github.com → Remove. Mac: Keychain Access → github.com → Delete. Then push again.
GH007: Your push would publish a private email address
Your email is hidden on GitHub. github.com/settings/emails shows your …@users.noreply.github.com address: set that as user.email, then git commit --amend --reset-author --no-edit and push again.
At school, git pull gives a strange error
Don't fight it. Step out of the repo (cd ..) and clone again under a new name: git clone <your-repo-link> elso-repo-2. GitHub has everything.
